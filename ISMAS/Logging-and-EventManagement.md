Logging and Event Management

ISO/IEC 27001 Security Monitoring Controls

Overview

Logging and event management are essential components of information security because they help organizations:

* Detect security incidents
* Monitor system activity
* Investigate suspicious behavior
* Demonstrate that security controls are operating effectively

Effective logging provides visibility into what is happening across systems, applications, and networks.

⸻

Logging

Overview

Logging is the process of recording activities and events generated by systems, applications, and users.

High-risk activities should be logged and stored securely to prevent attackers from modifying or deleting evidence.

⸻

Purpose of Logs

Logs support:

Incident Detection

Help identify:

* Unauthorized access
* Suspicious behavior
* Security attacks
* System failures

Investigation and Forensics

Logs provide evidence to:

* Understand what happened
* Identify affected systems
* Determine the cause of an incident

Control Verification

Logs help prove that security controls are:

* Active
* Operating correctly
* Producing expected results

⸻

Event Management

Overview

Event management involves collecting, analyzing, and correlating information from different sources to identify potential security issues.

Sources may include:

* Operating systems
* Applications
* Network devices
* Security tools

⸻

Event Collection

Organizations commonly use:

* System logs (e.g., syslog)
* Application logs
* Network device logs
* Central logging servers
* Security monitoring platforms

Centralized logging improves visibility and makes analysis easier.

⸻

Event Correlation

Event management systems analyze multiple events together to identify patterns.

Example:

Multiple failed logins
        ↓
Successful login from unusual location
        ↓
Possible account compromise
        ↓
Security investigation

⸻

Important Events to Log

Organizations should record security-relevant activities, including:

Access Events

* Unauthorized access attempts
* Failed login attempts
* Successful privileged access

Configuration Changes

* System configuration changes
* Security setting modifications
* Network changes

Data Changes

* Creation of sensitive data
* Modification of information
* Deletion of records

User Account Activity

* Creation of user accounts
* Changes to permissions
* Removal of accounts

System Alerts

* Security alarms
* Monitoring alerts
* Automated warnings

⸻

Events vs Incidents

A key security principle:

Not all events are incidents, but all events must be analyzed.

An event is simply an activity recorded by a system.

An incident occurs when an event is confirmed to negatively affect security.

Example:

Event → Analysis → Possible Threat → Confirmed Incident → Response

⸻

Log Protection

Logs themselves contain sensitive information and must be protected.

Organizations must ensure:

Confidentiality

Prevent unauthorized access to logs.

Examples:

* Access restrictions
* Encryption
* Authentication controls

Integrity

Prevent unauthorized modification or deletion.

Examples:

* Write protection
* Secure storage
* Access monitoring

Availability

Ensure logs are available when needed.

Examples:

* Backup storage
* Redundant logging systems
* Retention policies

⸻

Best Practices

Organizations should:

* Define what events must be logged
* Protect logs from tampering
* Review logs regularly
* Maintain appropriate retention periods
* Monitor for suspicious activity
* Synchronize system time for accurate investigation

⸻

Summary

Logging and event management enable organizations to monitor activity, detect threats, investigate incidents, and verify security controls.

Effective implementation requires:

* Capturing important security events
* Centralizing and analyzing logs
* Protecting log confidentiality, integrity, and availability
* Reviewing events to identify potential incidents

Strong logging practices are a foundation for effective incident detection, response, and overall information security management.

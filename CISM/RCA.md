# CISM Incident Operations: Root Cause Analysis (RCA)

## 1. Purpose
To identify the underlying architectural, operational, or governance failure that allowed a security incident to occur, shifting from reactive "firefighting" to proactive risk reduction.

## 2. Core Methodologies
* **5 Whys:** Iterative drill-down to bypass superficial symptoms.
* **Fishbone (Ishikawa):** Structural categorization (People, Process, Technology, Governance).
* **Fault Tree Analysis:** Deductive logic paths mapping system vulnerabilities.

## 3. Metrics for Success
* **Recurrence Rate:** The percentage of incidents that repeat due to the same root cause (Goal: 0%).
* **Action Item Closure SLA:** The time it takes technical teams to implement the resulting Corrective Action Plan.

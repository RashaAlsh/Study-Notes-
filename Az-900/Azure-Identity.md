# 2.4 Azure Identity, Access & Security

## Authentication vs Authorization

### Authentication (AuthN)
Authentication is the process of verifying a user's identity (proving who you are).

### Authorization (AuthZ)
Authorization determines what an authenticated user is allowed to access or perform.

---

# Microsoft Entra ID

Microsoft Entra ID (formerly Azure Active Directory) is Microsoft's cloud-based identity and access management (IAM) service.

It allows users to securely access:

- Internal resources
  - Corporate applications
  - On-premises applications
  - Custom cloud applications

- External resources
  - Microsoft 365
  - Azure Portal
  - SaaS applications

---

# Microsoft Entra Domain Services

Microsoft Entra Domain Services provides managed domain services without deploying or managing domain controllers.

Features include:

- Domain Join
- Group Policy
- LDAP
- Kerberos & NTLM authentication

Useful for running legacy applications in Azure that require traditional Active Directory features.

# Authentication Methods

## Single Sign-On (SSO)

Single Sign-On allows users to sign in once and access multiple applications without signing in repeatedly.

### Benefits

- Better user experience
- Fewer passwords to remember
- Reduced password fatigue
- Increased productivity

---

## Multi-Factor Authentication (MFA)

MFA increases security by requiring two or more authentication factors.

Authentication factors include:

- **Something you know**
  - Password
  - PIN

- **Something you have**
  - Trusted device
  - Phone

- **Something you are**
  - Fingerprint
  - Face recognition

### Microsoft Authenticator App

The Microsoft Authenticator app can be used:

- As a passwordless sign-in method
- As an MFA verification method
- During self-service password reset (SSPR)

---

## OATH Tokens

OATH (Open Authentication) is an open standard used to generate Time-based One-Time Passwords (TOTP).

### Software OATH Tokens

Generated by authentication apps such as:

- Microsoft Authenticator

The app stores a secret key and generates a new code every 30–60 seconds.

### Hardware OATH Tokens

Physical devices (key fobs) that display a changing one-time password every 30–60 seconds.

Useful when mobile devices aren't allowed.

---

## Passwordless Authentication

Passwordless authentication removes the need for traditional passwords while improving security.

### Windows Hello

Windows Hello uses:

- PIN
- Biometrics (Face/Fingerprint)

Supports authentication for:

- Microsoft accounts
- Active Directory
- Microsoft Entra ID
- FIDO2-supported services

### Benefits

- Eliminates password reuse
- Prevents password theft
- Reduces phishing attacks
- Protects against replay attacks

---

## FIDO2 Security Keys

FIDO2 uses public-key (asymmetric) cryptography instead of passwords.

Physical devices include:

- USB keys
- NFC keys

### Authentication Flow

1. User enters username.
2. Service sends a cryptographic challenge.
3. User confirms using the FIDO2 security key.
4. Service verifies the signed response.
5. Access is granted.

# External Identities

Microsoft Entra External ID enables secure collaboration with users outside your organization.

## B2B (Business-to-Business)

Allows external partners to access your applications using their own identities.

Supports:

- Microsoft accounts
- Enterprise identities
- SaaS applications

Provides seamless collaboration between trusted Entra ID organizations.

Commonly used for close business partnerships.

---

## B2C (Business-to-Consumer)

Allows organizations to build customer-facing applications.

Customers can sign in using:

- Microsoft accounts
- Google
- Facebook

- Other identity providers

---

## Multi-Tenant Organization

Allows multiple Entra ID tenants to collaborate using cross-tenant synchronization.

Useful for large organizations with multiple business units.

# Conditional Access

Conditional Access uses signals to evaluate every sign-in attempt and enforce security policies.

Common signals include:

- User identity
- Device
- Location
- Application
- Time
- Risk level

Possible actions:

- Allow access
- Block access
- Require MFA
- Require compliant device

---

# Azure Role-Based Access Control (RBAC)

Azure RBAC manages access to Azure resources.

It determines:

- Who can access resources
- What actions they can perform
- Which resources they can access

### Benefits

- Fine-grained permissions
- Built on Azure Resource Manager (ARM)
- Implements the Principle of Least Privilege

---

# Zero Trust

Zero Trust assumes no user or device is trusted automatically.

## Three Principles

### 1. Verify Explicitly

Always authenticate and authorize using all available signals.

Examples:

- Identity
- Device health
- Location
- Risk
- Application

---

### 2. Use Least Privilege Access

Provide only the minimum permissions required.

Techniques include:

- Just-In-Time (JIT) access
- Just-Enough Access (JEA)
- Risk-based policies

---

### 3. Assume Breach

Assume attackers may already be inside the network.

Mitigation strategies:

- Network segmentation
- End-to-end encryption
- Continuous monitoring
- Threat analytics

---

# Traditional Security vs Zero Trust

| Traditional Security | Zero Trust |
|----------------------|------------|
| Trust based on network perimeter | Trust based on identity |
| Internal network is trusted | No implicit trust |
| Verify once | Verify continuously |
| Broad access | Least privilege access |
| Perimeter-focused security | Identity, device, data, and application security |

Zero Trust also emphasizes:

- Strong authentication
- Device compliance
- Approved applications only
- Data classification and encryption
- Infrastructure security
- Continuous monitoring
- Network segmentation

---

# Defense in Depth

Defense in Depth is a layered security strategy where multiple security controls protect resources.

Security layers include:

1. Physical Security
2. Identity & Access
3. Perimeter
4. Network
5. Compute
6. Application
7. Data

If one layer is compromised, additional layers continue protecting the system.

# AZ-900 Exam Tips

- **AuthN** = Verify identity (Who are you?)
- **AuthZ** = Determine permissions (What can you do?)
- **SSO** = One sign-in for multiple applications.
- **MFA** = Two or more authentication factors.
- **Passwordless** = Windows Hello, Microsoft Authenticator, FIDO2.
- **B2B** = External business partners.
- **B2C** = Customers and consumers.
- **Conditional Access** = Uses signals to allow, block, or require MFA.
- **RBAC** = Controls access to Azure resources.
- **Zero Trust** = Verify explicitly, use least privilege, assume breach.
- **Defense in Depth** = Multiple layers of security.
- **Microsoft Defender for Cloud** = Security posture management and threat protection across Azure, on-premises, AWS, and GCP.
